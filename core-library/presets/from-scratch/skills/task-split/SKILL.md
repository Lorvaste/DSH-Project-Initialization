# 任务拆分（task-split）

目标：基于冻结的 spec.md，按**用户理解的功能域**生成任务拆分初稿 Reference/tasks.md。对应流程状态机 task-breakdown。

## 执行步骤

### 1. 读取规格

- 读取 Reference/spec.md（已冻结）
- 功能域清单取自 **spec §0**（权威载体，不依赖访谈记录）

### 2. 按功能域组织任务

- **不按固定细则机械拆分**——以用户理解的功能域为组织维度
- 每个功能域下列任务；任务粒度由用户决定（可粗可细）
- AI 只按域组织，不规定粒度；粒度不合适用户可随时调整

### 3. 生成 tasks.md

写入 `Reference/tasks.md`，结构（按本 skill 内嵌模板）：

```markdown
# tasks.md — 任务拆分（初稿）

## 元信息
关联规格版本：vX.Y

## 功能域（用户理解，问答④确认）
| 域 ID | 功能域 | 说明 | 关联规格条目 |
| MOD-01 | 用户管理 | 注册/登录/资料 | F-01, F-02, D-01 |

## 任务清单（按功能域组织）
### MOD-01 用户管理
| ID | 任务 | 关联规格 | 落点 | 依赖 | 状态 |
| MOD-01-T01 | 注册表单 | F-01 | Frontend/ | - | 待办 |
```

- 域 ID：`MOD-xx`；任务 ID：`MOD-xx-Tyy`（域内编号，可追溯）
- **落点列**：任务产物的归属目录（如 Frontend//Backend//Embedded//Model/；复合项目必填——追溯矩阵"需求↔任务↔产物↔验收"的产物环节）；**无任何类型子结构的项目（纯 CLI/纯本地工具）用 `./` 表示项目根**
- 每任务标注关联规格条目（追溯链：功能域 ↔ 规格 ↔ 任务）
- **范围声明（R-xx）不产生任务**：R 类条目不映射任务属正常（排除项无实现），tasks.md 元信息注明「R 条目不产生任务」便于矩阵自查

### 3.5 生成域开发骨架（可选，由用户决定）

- **任务拆分完成并确认后，询问用户是否启用域开发骨架**（一次一问，不默认启用）
- 用户选择**启用**：为每个功能域（MOD-xx）生成域骨架 `Reference/domains/MOD-xx/`——模仿默认骨架的文档结构，只保留域相关：

```
Reference/domains/MOD-01/
├── README.md     域自述：目标/范围/关联规格条目/涉及子结构落点
├── Rules.md      域规则：全局裁剪（适用本域章节）+ 域细化条目
├── Structure.md  域结构：域内组织（任务/产物落点）
├── Progress.md   域进度：任务状态（与 tasks.md 同步）
└── plan.md       域任务清单：MOD-xx-Tyy + 依赖 + 状态
```

- **域规则**：从项目 Rules.md 裁剪适用本域的章节（git/提交等通用规则仅引用不复制）+ 域内细化（全局规则在本域的具体化，如"报警判定在设备端 Embedded/、提醒在 Frontend/"；域细化可引用 interview skill 的领域遗漏模板相关维度）
- **全局规则优先**：域规则与全局冲突时全局胜（见 Rules.md 0.1 优先级链）
- **仅适用当前域**：不跨域引用规则
- 裁剪与细化自动完成 → **用户确认后生效**
- 用户选择**不启用**：跳过生成，在 tasks.md 元信息**与 Progress.md 双处**记录「域开发骨架：未启用」
- **补生成入口**：后续会话执行本小节（3.5）即可补生成（不启用或新增功能域后都可补）；启用/生成状态记录到 Progress.md（域骨架无独立状态机状态，以 Progress.md 记录为准）

### 4. 确认与收尾

- tasks.md 由用户确认（初稿允许后续会话细化）
- **追溯差集自检（刚性，收尾前执行）**：对照 spec §0/条目清单检查——每个 F/D/I 条目至少被一个任务引用、每个任务引用的条目 ID 存在且域归属一致；**未被任何任务引用的 F/D/I 条目必须补齐任务或显式说明原因**（R 类排除项豁免，见上）；结果记录到 tasks.md 元信息（如「差集自检：全部闭合 / 豁免 R-xx」）
- 场景终态：文档推送（git add/commit/push，push 可选——沙箱拦截时引导权限升级）
- 推送后场景结束（done）：交付总结（spec 版本、任务数、远端状态）
- 状态写入 Progress.md

## 防漂移红旗表（Red Flags——这些想法意味着 STOP）

| 合理化念头 | 必须改为 |
|---|---|
| "按规格条目机械拆任务就行" | 按用户理解的功能域组织，粒度用户定 |
| "任务关联规格差不多对上就行" | 追溯链必须准确：任务 ↔ 规格条目 ID |
| "用户没反对就是同意" | 沉默≠同意，tasks.md 必须显式确认 |

## 规则分级与优先级

- **刚性（Rigid，必须执行）**：按功能域组织 / 追溯链标注 / tasks.md 用户确认
- **弹性（Flexible，适配原则）**：任务粒度（用户定）/ 初稿详略
- **优先级链**：用户拍板 > 全局规则 > 域内规则 > 场景规则（完整链见 Rules.md 0.1）

## 工程准则

- **先查证，不假设**：任务拆分以冻结的 spec.md 为准，不凭访谈记忆补条目
- **写盘即记忆**：tasks.md 落盘 + 状态记录 Progress.md
