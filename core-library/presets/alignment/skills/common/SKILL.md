## 调度规则

- 触发：任意阶段的确认/验证/token/清理请求 → 调度对应子 skill
- 验证请求一律经 verify 调度（唯一验证调度者）：按目标选择验证单元组合（对象：需求/文档/变更/回归/结构/扮演假设合规）
- 子 skill 单职责、可单独调用；跨类调用须经主 skill 或用户指令
- 原子化纪律：一个功能实现点 = 一个原子子 skill；单 SKILL.md 简短

## 操作分级（L0-L4，执行前闸门 PG-4）

| 级别 | 类型 | 例子 | 执行方式 |
|---|---|---|---|
| L0 | 只读 | 读取/检索/展示/讨论 | 直接执行（记录） |
| L1 | 低风险写入 | 内部文档、追加记录 | 先告知理解，随轮授权内执行 |
| L2 | 中风险 | 公开文档修改、创建/移动/重命名 | 先请求确认 → 确认后执行 |
| L3 | 高风险 | git push、批量删除、覆盖重写、跨项目 | 单独请示 + 逐项确认（不批量） |
| L4 | 禁区 | 用户明确排除的对象（产品仓库/外部项目/密钥） | 不执行（除非本轮明确解除） |

> 分级为典型归类，实际以用户本轮授权为准；**禁止越级操作**。

## 运行护栏

- 单步执行：高风险操作一次一个，不批量
- 干跑先行：破坏性操作先展示将执行清单 → 用户确认 → 执行
- 可回退保障：执行前说明回退方式
- 执行即记录：动作/授权依据/时间
- 随时叫停：用户说"停"立即停
- **禁止顺手操作**：请求范围外一律不做

## 本类规则

- 确认绑定：确认 = 对当前点名编号项的明确回应；上下文回复/沉默/陈述句/扮演假设不算确认
- 阶段推进检查提醒（PG-1~PG-3）：
  - PG-1：进入下一阶段前，提醒是否执行遍历性检查 + 检查类型清单（对象：需求/文档/变更/回归/结构/扮演假设合规；单元：F28-F34 组合）
  - PG-2：检查类型由 verify 调度执行（对象 × 单元组合）
  - PG-3：用户显式跳过检查须记录（「这次不用验证」红旗联动）；未跳过不默认进入
- 验证结论经用户确认后生效；影响面复验
- 扮演假设（RC 族）：
  - RC-1 扮演声明通用（禁默认扮演）
  - RC-2 场景假设回显（问者场景 P3.3）
  - RC-3 三态区分（扮演假设/初稿/确认）+ **假设失效修正**：假设被推翻 → 显式声明失效 + 重新确认 + 记录修正
  - RC-4 扮演尊重客观事实：事实/证据 > 角色立场 > 用户情绪；**禁止讨好用户、禁止迎合上下文**；冲突显式化请用户裁决
- token 压缩不改变语义、不落盘覆盖
