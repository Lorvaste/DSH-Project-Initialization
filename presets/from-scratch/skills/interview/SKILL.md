# 访谈（interview）

目标：把一句话想法展开为可冻结的规格，防「需求模糊」与「AI 理解偏」。对应流程状态机 interview（含六步子状态机）。

## 问答六步逻辑（顺序推进）

```
① 想做什么 → ② 功能实现范围 → ③ 细则确认 → ④ 结构化拆分与确认
→ ⑤ 遍历性验证逻辑与遗漏并修复 → ⑥ 确认成档
```

### ① 想做什么

- 用户自由描述想法（一句话起）
- AI 复述理解并确认（复述不是复读，是理解后的重述）
- 体量判定：AI 判定深度档位（浅/中/深）并告知用户，用户可纠正；档位只决定提问强度建议，**不设问题数上限**

### ② 功能实现范围

- 功能清单：要做什么（逐项记录）
- 边界：明确不做什么（排除项/非目标）
- 实现约束初确认：技术栈、运行环境、偏好

### ③ 细则确认

- 参数、边界条件、界面行为、异常处理
- **一次只问一个问题**；问题尽量带选项/示例降低回答成本

### ④ 结构化拆分与确认

- 按**用户理解的功能域**拆分：用户描述功能域划分（如：用户管理域/订单域），逐域确认
- 每域关联规格条目
- 任务粒度由用户决定，AI 只按域组织不规定粒度

### ⑤ 遍历性验证逻辑与遗漏并修复（升级版：三层遍历 + 七维度 + 领域模板）

**三层遍历**：
- **目标层**：①想做什么的目标对齐——所有规格是否服务于用户目标（防跑题/范围膨胀）
- **域层**：功能域完整性——④确认的功能域（MOD-xx）是否覆盖目标所需（用户漏域检查）
- **条目层**：④的条目清单逐条过检

**检查维度（七项）**：
1. **逻辑自洽**：条目间矛盾、条件不闭环
2. **覆盖完整性**：四层规格（功能/细节/范围/实现）缺口
3. **遗漏**：边界、异常未定义（结合领域模板，见下）
4. **可验证性**：每条目必须可被事实/测试/检查验证（不可验证=未来无法验收，必须改写）
5. **歧义性**：条目是否存在多种理解（多解必须澄清，禁止留歧义）
6. **依赖闭环**：前置条件是否完整（如"登录"依赖"注册"）
7. **数量合理性**：条目数量与体量匹配（浅档条目异常多=拆分粒度问题，回④调整）

**领域遗漏模板（软件 v1）**：
- 输入：校验/格式/必填/非法值
- 异常：错误提示/失败回滚/超时重试
- 边界：空状态/极值/并发/权限
- 数据：持久化/备份/隐私
- 环境：部署/配置/平台差异
- **复合/硬件补丁（场景类型含实体时追加）**：供电（电源/功耗）/ 环境范围（温度/湿度/安装条件）/ 失效模式（传感器失效/通信中断/断电恢复）/ 校准与精度 / 通信（协议/中断/重连）/ 安全（电气/发热/结构强度）
- （实体领域模板 v2 设计）

**检查过程可审计**：AI 按维度逐项报告检查过程与结果（如"逻辑自洽：检 N 条，发现 2 条矛盾"），不只给问题清单——用户能验证检查本身。

**修复与复验**：问题清单 → 用户确认 → 修复 → **影响面复验**（只复验受影响关联条目，不全部重检）→ 循环至无问题。

**通过标准（显式闸门，全部满足才进入⑥）**：
- 四层规格全覆盖（功能/细节/范围/实现）
- 0 逻辑矛盾、0 歧义条目
- 100% 条目可验证
- 每条规格可回溯到①的目标
- 领域模板全部过检（软件 v1）

**问题类型统计沉淀**：发现的问题按类型记录到 Other/（如 verification-issues.md），沉淀领域模板——同类项目常见遗漏进入模板，形成学习闭环。

### ⑥ 确认成档

- 进入冻结（freeze skill）：AI 结构化复述 → 逐条确认（已确认/待定/驳回）
- 遍历验证未通过不成档

## 准则（五组）

- **提问准则**：一次一问；带选项/示例降低回答成本；不诱导（不预设答案）；不评判（用户专业错误就事论事纠正）
- **记录准则**：每个回答显式记录（需求说明书），AI 随时可复述已记内容；隐式假设逼出（"正常/自然/按惯例"等模糊词必须追问具体含义）；矛盾检测（前后冲突指出请用户裁决）
- **收敛准则**：AI 不得为问而问；每步完成提示下一步，由用户决定继续或结束；**以用户确定完成为准**
- **冻结准则**：复述必须是结构化理解；未确认条目不进规格；遍历验证未通过不成档
- **角色准则**：AI 是引导者不是决策者；用户是唯一权威；全程可回溯（任何一步可回到之前问题）

## 防漂移红旗表（Red Flags——这些想法意味着 STOP）

| 合理化念头 | 必须改为 |
|---|---|
| "用户应该已经确认了，不用再复述" | 显式复述并等用户确认 |
| "这次很简单，不用遍历验证" | 遍历验证是刚性闸门，不跳过（除非用户显式要求跳过并记录）|
| "我理解了，不用逐条确认" | 逐条确认，未确认条目不进 spec |
| "用户没反对就是同意" | 沉默≠同意，必须显式确认 |
| "改一下没问题，不用记录" | 变更必须显式记录，禁止静默漂移 |

## 规则分级与优先级

- **刚性（Rigid，必须执行）**：规格冻结逐条确认 / 遍历性验证 / 变更记录显式化 / 状态机闸门
- **弹性（Flexible，适配原则）**：提问方式 / 访谈深度（以用户确定完成为准）/ 任务粒度（用户定）
- **优先级链**：用户拍板 > 场景规则 > AI 建议

## 工程准则

- **先查证，不假设**：不确定的事实（用户意图/术语含义/环境行为）先查证——读文档、实测、或直接问用户；绝不凭空推断（"不要虚假假设"）
- **写盘即记忆**：上下文是易失内存，文件是持久磁盘——访谈记录/状态/决策持续落盘（Other/ + Progress.md），每 2-3 轮回答落盘一次
- **WHAT 不 HOW**：向用户复述确认时给 WHAT 级描述，实现方式不擅自定

## 产出

- 访谈全程记录保留到 **Other/interview.md**（需求说明书，可回溯；每 2-3 轮回答落盘一次）
- 场景类型（纯软件/纯实体/复合）在访谈中确定后，**执行 scaffold skill 阶段二**（类型子结构生成，按项目 Rules.md 第四章）→ 再进入冻结（freeze skill）
- 访谈结束后按 freeze skill 冻结规格
