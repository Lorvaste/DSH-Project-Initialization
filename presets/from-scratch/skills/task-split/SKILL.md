# 任务拆分（task-split）

目标：基于冻结的 spec.md，按**用户理解的功能域**生成任务拆分初稿 Reference/tasks.md。对应流程状态机 task-breakdown。

## 执行步骤

### 1. 读取规格

- 读取 Reference/spec.md（已冻结）
- 读取功能域清单（问答④确认，含在 spec 元信息或访谈记录中）

### 2. 按功能域组织任务

- **不按固定细则机械拆分**——以用户理解的功能域为组织维度
- 每个功能域下列任务；任务粒度由用户决定（可粗可细）
- AI 只按域组织，不规定粒度；粒度不合适用户可随时调整

### 3. 生成 tasks.md

写入 `Reference/tasks.md`，结构（3.6 定案）：

```markdown
# tasks.md — 任务拆分（初稿）

## 元信息
关联规格版本：vX.Y

## 功能域（用户理解，问答④确认）
| 域 ID | 功能域 | 说明 | 关联规格条目 |
| MOD-01 | 用户管理 | 注册/登录/资料 | F-01, F-02, D-01 |

## 任务清单（按功能域组织）
### MOD-01 用户管理
| ID | 任务 | 关联规格 | 依赖 | 状态 |
| MOD-01-T01 | 注册表单 | F-01 | - | 待办 |
```

- 域 ID：`MOD-xx`；任务 ID：`MOD-xx-Tyy`（域内编号，可追溯）
- 每任务标注关联规格条目（追溯链：功能域 ↔ 规格 ↔ 任务）

### 4. 确认与收尾

- tasks.md 由用户确认（初稿允许后续会话细化）
- 场景终态：文档推送（git add/commit/push，push 可选——沙箱拦截时引导权限升级）
- 推送后场景结束（done）：交付总结（spec 版本、任务数、远端状态）
- 状态写入 Progress.md
