# 冻结成档（freeze）

目标：把访谈成果冻结为权威规格文档 Reference/spec.md（纯需求描述），防「理解偏」与「冻结后漂移」。对应流程状态机 freeze → spec-final。

## 执行步骤

### 1. 结构化复述

- AI 把访谈成果按四段结构复述（理解后的重述，不是逐字重复）：
  - **功能**（做什么，F-xx 条目）
  - **细节**（参数、边界、界面，D-xx 条目）
  - **范围**（不做什么，R-xx 条目）
  - **实现**（技术栈、约束，I-xx 条目）
- 每段附功能域归属（MOD-xx，来自访谈④）

### 2. 逐条确认

- 每条规格条目由用户确认：**已确认 / 待定 / 驳回**
- 待定：标记后继续；驳回：重新澄清后再次确认
- 未确认条目不进规格文档
- 闸门：全部条目「已确认」→ 才允许成档

### 3. 生成 spec.md 初版终稿

写入 `Reference/spec.md`，结构（3.6 定案）：

```markdown
# spec.md — 项目规格（v1.0 冻结）

## 元信息
项目名 / 场景类型（纯软件·纯实体·复合）/ 体量档位（浅·中·深）/
冻结版本 / 冻结日期 / 确认方式（AI 复述 + 用户逐条确认）

## 1. 项目概述（想做什么）
一句话定位 + 目标价值 + 核心用户/用途

## 2. 功能规格（做什么）
| ID | 功能 | 状态 |
（不设优先级；spec 为纯需求描述）

## 3. 细节规格（参数·边界·界面）
| ID | 关联功能 | 细节 | 边界/异常 | 状态 |

## 4. 范围声明（不做什么）
| ID | 排除项 | 原因 | 状态 |

## 5. 实现约束（技术栈·偏好）
| ID | 约束 | 说明 | 状态 |

## 6. 变更记录
| 版本 | 日期 | 变更 | 原因 | 确认 |
```

- 条目编号：F/D/R/I 前缀 + 序号（追溯锚点）；状态冻结时全部「已确认」
- 实体产品规格：单独结构（v2，暂不生成）

### 4. 闸门与收尾

- 闸门：spec.md 初版终稿写入 Reference/ 且内容与确认一致 → 进入任务拆分（task-split skill）
- 冻结后变更：显式记录到 spec 变更记录 + Progress.md，禁止静默漂移
- 状态写入 Progress.md
